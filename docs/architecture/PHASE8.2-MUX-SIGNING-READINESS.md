## Expected signing format (existing Wave 2 code, `src/lib/mux-signed-playback.ts`)

| Item | Value |
|------|-------|
| Algorithm | RS256 (Node `crypto`, no `@mux/mux-node`) |
| `MUX_SIGNING_KEY_ID` | Mux signing key id (the `id` from Mux signing-key creation); used as JWT header `kid` and claim `kid` |
| `MUX_SIGNING_PRIVATE_KEY` | base64-encoded PEM, exactly as Mux returns `private_key`. Raw PEM (with `\n` escapes) is also accepted |
| Claims | `sub` = playback id, `aud` = `"v"`, `exp` = now + TTL, `kid` |
| TTL | `MUX_PLAYBACK_TOKEN_TTL_SEC` = 600 s (10 min) |
| Authorization | `recording-playback-auth.ts` authorizes first and never signs a client-supplied playback id (`PLAYBACK_ID_NOT_ACCEPTED`) |
| Fixture tokens | HMAC fixture tokens are staging-only and never used for real Mux ids |
| Ingest | `recording-mux-ingest.ts`: signed-only direct upload; public playback ids blocked; result `teacher_review` |

No new signing implementation is needed. The key only has to be provisioned.
